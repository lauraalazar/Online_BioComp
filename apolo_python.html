Uso de Apolo#

Una introducción del servidor de EAFIT Apolo se encuentra aquí. Una vez cumplidos los requisitos, se puede acceder a Apolo por vía de putty o una terminal de linux (ya sea wsl o cygwin), previo inicio del Global Protect

ssh lsalazarj@apolo.eafit.edu.co

Una vez entras a Apolo, estas en tu Home. Allí puedes comenzar a crear archivos y directorios con los comandos de linux. Vamos a crear un directorio y a copiar allí archivos desde nuestro PC. Primero creamos el directorio

mkdir biocomp_python #o el nombre que quieras ponerle

Para copiar archivos a este directorio, vamos a ir a nuestro PC, al directorio donde se encuentran los archvios de Ecoli_pho.fa y sus mutantes. Desde la terminal se puede copiar este archivo al directorio de Apolo utilizando el comando scp <archivo a copiarr> <directori a donde va>

scp *.fasta lsalazarj@apolo.eafit.edu.co:/home/lsalazarj/biocomp_python

Verifique que los archivos si se hayan copiado correctamente en Apolo.

Cómo correr programas en Apolo#

En Apolo se deben correr programas por medio de scripts, ya que no hay una interfase gráfica. Algunos programas que utilizamos están instalados, sin embargo a veces necesitamos algunas versiones específicas u otras librerías y para esto debemos cargar el módulo correspondientes. Para ver la disponibilidad de módulos utilizamos:

module avail

Para obtener los programas necesarios para correr los scripts, se necesita instalarlos por medios de ambientes conda. Este es un gestor de programas que permite que haya múltiples versiones del programa y que se instale con todo lo necesario

module load python/3.6.0_miniconda-4.3.11_gcc-11.2.0
conda create -n biopython
conda activate biopython
conda install -c conda-forge biopython
conda install -c conda-forge pandas

Debemos salir y volver a entrar a apolo para chequear la instalación. Una vez realizamos el login, activamos el ambiente de bioppython y comenzamos python

source activate biopython
python

import Bio
print(Bio.__version__)

Si sale un error después de llamar la librería es porque hay un error de instalación y hay que repetirla.

Normalmente ejecutaríamos la tarea de la siguiente forma en la terminal

source activate biopython
python ExamenPython.py

Sin embargo en Apolo no se deben ejecutar scripts directamente. Esto se realiza mediante un script slurm

Correr programas por medio de un script SLURM#

Un script slurm es un script ejecutable en bash (``.sh’’) tiene la siguiente estructura:

  1. Un encabezado con el usuario

  2. Parámetros de SBATCH: aquí se especifica: la partición (learning en neustro caso), los nodos a usar, el tiempo, el email del usuario

  3. El cuerpo del script: aquí se deben cargar los módulos, activar los ambientes e insertar el código a ejecutar

#!/bin/bash #==============================================================================

==============================================================================#

#==============================================================================

Slurm Job Submission Script#

#

Generated by: Interactive Slurm Script Generator v1.0.1#

Author: lsalazarj#

Generated On: Tue Jul 29 15:44:17 -05 2025#

#

==============================================================================#

#============================================================================== #SBATCH –job-name=”ecoli_mutantes” #SBATCH –partition=learning #SBATCH –nodes=1 #SBATCH –ntasks=1 #SBATCH –mem=4G

#

#SBATCH –time=00:10:00 #SBATCH –output=logs/%x_%j.out # Standard output log (%x = job name, %j = job ID) #SBATCH –error=logs/%x_%j.err # Standard error log #SBATCH –mail-type=ALL # Mail events (NONE, BEGIN, END, FAIL, ALL) #SBATCH –mail-user=lsalazarj@eafit.edu.co # Your email address from user input

#==============================================================================

echo “=================================================” echo “Starting job \(SLURM_JOB_ID on host \)(hostname)” echo “Job name: \(SLURM_JOB_NAME" echo "Partition: \)SLURM_JOB_PARTITION” echo “Number of nodes: \(SLURM_NNODES" echo "Total number of tasks: \)SLURM_NTASKS” echo “=================================================” echo

Afrotunadamente este script se genera a partir de una plantilla automática con algunos datos que le itnroducimos

create_slurm

Y vamos llenando los campos que se piden. Para correr este script utilizamos el comando

sbatch script.sh

Y para ver los detalles de la ejecución

squeue 
my_jobs

Una vez termina de correr el script, se generan dos archivos: .err y .out dentro de un directorio /log, los cuales contienen, respectivamente, los errores, en caso de haber (si no hay el archivo se genera pero está vacío) y los output.
